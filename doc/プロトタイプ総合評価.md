# Re:Tailor プロトタイプ総合評価

最終更新日：2026年9月25日

## 1. 評価概要

現段階のプロトタイプは、主要画面の見た目と基本的なページ遷移を確認する用途では利用できる。一方で、要件書が定める「主要操作を次の画面までつなげる」「仮リンクやリンク切れを残さない」「画面間で表示データを一貫させる」という受入条件は未達である。

**総合評価：80 / 100**

| 評価領域 | 評価 | コメント |
| --- | --- | --- |
| 画面の網羅性 | B | トップ、商品詳細、購入、マイページ、出品、診断など主要画面は揃っている |
| 見た目・操作感 | B- | 画面単位では確認できるが、フォント、ボタン、余白の統一に差がある |
| 画面遷移 | C | 基本導線はあるが、仮リンク、リンク切れ、未接続フォームが残る |
| データ連携 | D | 商品情報、購入情報、出品情報が画面ごとに固定・分散している |
| 入力・状態管理 | D | 入力エラー、完了、空状態、対象なしの状態が不足している |
| アクセシビリティ | C- | 一部の入力ラベルやHTML構造、画像の代替テキストに改善余地がある |
| レスポンシブ対応 | C- | 一部画面で固定幅・固定余白があり、狭い画面で崩れる可能性がある |

## 2. 重大な課題

### P0：商品詳細から購入する商品が一致しない

商品詳細の購入ボタンが商品IDを購入画面へ渡していない。購入画面は商品IDがない場合に固定の商品を表示するため、閲覧していた商品と購入対象が一致しない可能性がある。

対象：

- `プロトタイプ/static/detail.js`
- `プロトタイプ/static/script.js`

対応方針：商品詳細から `buy.html?items=商品ID` のようにIDを引き継ぎ、共通の商品マスタから購入画面を描画する。

### P0：商品データが画面ごとに分散している

同じ商品IDでも、トップ、商品詳細、購入画面、購入履歴で商品名・価格・カテゴリ・出品者が一致していない。

対象：

- `プロトタイプ/static/top-script.js`
- `プロトタイプ/static/detail.js`
- `プロトタイプ/static/script.js`
- `プロトタイプ/static/purchase-history.js`

対応方針：商品情報を共通のJSONまたは共通JavaScriptデータにまとめ、各画面が同じデータを参照する。

### P0：サインアップとログインが実際のフォーム操作になっていない

サインアップはプロトタイプ内に存在しない `/signup` へ送信する。ログインは入力値を検証せず、空欄でもトップページへ遷移できる。また、入力ボタンをアンカーで囲む不正な構造がある。

対象：

- `プロトタイプ/templates/signup.html`
- `プロトタイプ/templates/login.html`

対応方針：仮実装としても必須入力、メール形式、パスワードエラーを表示し、入力成功時は存在する完了状態またはトップページへ遷移する。

## 3. 高優先度の課題

### P1：出品内容が保存されない

出品フォームに入力した商品名、カテゴリ、価格、状態、配送情報などが出品一覧やマイページに反映されない。「出品する」も入力内容を送信しないリンクになっている。

対象：

- `プロトタイプ/templates/syuppin.html`
- `プロトタイプ/templates/syuppin_itiran.html`
- `プロトタイプ/templates/naiyouhensyuu.html`

対応方針：`form` と `name` を設定し、仮実装では `localStorage` に保存する。必須入力エラー、保存完了、一覧への反映を用意する。

### P1：購入確定後に購入履歴が更新されない

購入確定ボタンは固定の購入履歴画面へ遷移するだけで、今回の注文内容を購入履歴へ保存していない。購入完了状態もない。

対象：

- `プロトタイプ/static/confirm.js`
- `プロトタイプ/static/purchase-history.js`

対応方針：購入確定時に注文日時、レシート番号、商品、合計金額を保存し、購入履歴一覧で表示する。

### P1：リンク切れ・仮リンクが残っている

確認できた問題：

- `about-index.html` が存在しない `index.html` を参照している
- トップページのロゴ、ホーム、コンタクトなどに `#` が残っている
- 検索画面の送信先が `#` になっている

対応方針：存在する画面へ接続するか、未実装であることを要件書に記録して仮リンクを残さない。

### P1：取り下げ操作に確認と保存処理がない

取り下げ理由を入力する画面はあるが、取り下げ確定時の理由チェック、確認ダイアログ、一覧からの非表示処理がない。

対象：

- `プロトタイプ/templates/torisage.html`

## 4. 中優先度の課題

- 商品IDが存在しない場合に、商品詳細が商品ID 1へフォールバックする
- お気に入り、出品一覧、マイページの情報が他画面と連動していない
- 購入履歴にデータなしの状態がない
- 検索結果の商品カードから商品詳細へ遷移できない
- レビュー投稿画面の商品名・出品者が固定表示になっている
- 出品画面の入力欄に一部 `label`、`id`、`name` が不足している
- マイページのタブに対応する `aria-labelledby` のIDがない
- 出品画面に狭い画面用のレイアウト調整がない
- ログイン画面のフォーム幅が固定されている
- トップページのCSS変数に未定義の参照がある
- Google Fontsや外部画像に依存しており、直接HTMLを開いた場合の代替表示が不足している

## 5. 現在できていること

- HTMLを `プロトタイプ/templates/`、CSSとJavaScriptを `プロトタイプ/static/` に配置している
- マイページから購入履歴一覧へ遷移できる
- 購入履歴一覧から購入詳細へ遷移できる
- 購入詳細からレビュー投稿画面へ遷移できる
- 購入詳細から購入商品を使うコーディネート診断へ遷移できる
- コーディネート診断は購入IDを受け取った場合、マイクローゼットの商品ではなく購入商品を選択アイテムとして表示する
- レビュー画面の戻る先をトップページに統一している
- 出品画面に配送方法、発送まで、送料、返品・交換を追加している
- トップページのカテゴリを出品時のカテゴリ項目に合わせている
- バッグ商品を「バッグ」カテゴリで絞り込める
- 購入履歴、購入詳細、コーディネート診断関連のHTML・CSS・JavaScriptは200行以内で作成している
- 変更対象のJavaScript構文と主要ファイルのエディター診断は問題ない
- 全JavaScriptファイルの構文確認でエラーがない
- 相対リンク検査でリンク切れが0件になっている

1. 共通の商品マスタを作成し、全画面の商品情報を統一する
2. 商品詳細から購入画面への商品ID引き継ぎを修正する
3. 購入確定時に購入履歴を更新する
4. 出品フォームの保存と出品一覧への反映を実装する

6. `#`、存在しないファイル、未接続フォームを整理する
7. 空状態、入力エラー、完了、対象なしの状態を追加する
8. 共通CSSとフォーム部品を整理する
9. モバイル表示とアクセシビリティを確認する
